# Assignment Module — API Documentation

The `Assignment` module owns the `assignments` table — the reusable **assignment template** (topic, exercise count, word count, allowed file types, AI-evaluation config) attached to a `Course`, as distinct from `StudentAssignment` (the per-enrollment instance created from a template — see `StudentAssignment.md`). It covers template CRUD for both the regular-course flow and a parallel "bootcamp" flow, plus a CSV export of the template listing. See [`./_COMMON_CONVENTIONS.md`](./_COMMON_CONVENTIONS.md) for app-wide envelope/error/pagination conventions — this file only calls out deviations.

**Module-wide auth:** every route in `Modules/Assignment/Routes/api.php` is `auth:sanctum` + `json.response`, prefix `v1`. No per-route deviation.

**Class layout:** two controllers share one trait. `AssignmentController` (regular-course template CRUD, `index`/`store`/`changeStatus`/`activityLogs`/`update`) also pulls in `App\Traits\ActivationAndDeactivationProcess` for its bulk activate/deactivate logging. `BootcampAssignmentController` (`index`/`store`/`update`) is the bootcamp-flavored parallel path — near-identical validation/creation logic via a *different* pair of FormRequests, but the same underlying `assignments` table and the same `AssignmentTrait`. Both controllers `use AssignmentTrait` (`Modules/Assignment/Http/Traits/AssignmentTrait.php`), which holds the actual `createAssignment()`/`updateAssignment()`/`export()`/`calculateRangeForCursor()` bodies — every method below is noted as living in its controller or in this shared trait.

---

## `GET /v1/assignment-library` — `index()` (`AssignmentController`)
- Query: `rows` (optional int, default 15).
- **Success response:** `AssignmentResource::collection($this->assignmentRepo->allWithSearch(['*'], $rows))->additional(['meta' => ['total_assignment' => count(...), 'range' => ...]])`. `allWithSearch()` cursor-paginates `Assignment::query()->where('course_id', request('course_id'))->groupBy('topic_id')->latest('id')` — **`course_id` is a hard `where`, not `when`-guarded**: if the caller omits the `course_id` query param, the underlying SQL still runs `WHERE course_id = NULL`, which matches zero rows (MySQL `= NULL` is never true) — this endpoint silently returns an empty list rather than "all assignments" if `course_id` is omitted, with no validation error to signal that. Also note `total_assignment` in `meta` is `count()` of an array from `totalAssignment()` (a plain `->get(['id','course_id','topic_id'])` on the same filtered/grouped query) — a second, separate, unfiltered-by-cursor query, not derived from the cursor's own `total`.
- `AssignmentResource` fields: raw `id`,`status`,`word_count`,`assignment_download_file`,`number_of_exercises`,`assignment_code`,`allowed_file_types`,`is_ai_enabled`,`assignment_instruction_link`,`assignment_sample_feedback_link`, plus `ai_model` (nested `{id,name,version,description,is_default,gemini_model_id}` or `null`), `created_at` (`Y-m-d G:i:s` — note `G` not `H`, so no leading zero on the hour), **`plagiarism` as string `"Yes"`/`"No"`** (not boolean), **`assignment_type` as string `"Written"`/`"Subjective"`** (not the raw `0`/`1`), `topic` (nested `TopicResource`), `tags` (`TagResource::collection`).

## `POST /v1/assignment-library` — `store()` (`AssignmentController`)
- **Request body** (`StoreAssignmentRequest`, `authorize()` always `true`): `course_id` required `exists:courses,id`; `assignment_topic` required max:255; `number_of_exercises` required numeric 1–10; `assignment_type` required int `in:0,1`; `allowed_file_types` optional array, each `in:pdf,doc,docx,zip`; `plagiarism` required boolean; `word_count` required integer; `ref_assignment_no` optional integer; `ai_model_id` optional `exists:ai_models,id`; `is_ai_enabled` optional boolean; `assignment_instruction_link`/`assignment_sample_feedback_link` optional string; `assignment_instruction_file`/`assignment_sample_feedback_file` — file (`pdf,doc,docx`, max 10240KB) if uploaded as a file, else optional string (branches on `hasFile()` at rule-build time); `status` required boolean; `package_id` optional `exists:packages,id`; `assignment_download_file` optional URL; `topic_content` optional array of `{title required max:255, link required url max:255, note required string}` (each field only required if `topic_content` present at all — an empty array still satisfies `nullable`); `tags` optional array of `{key required int, value required string max:255}`.
- **Success response:** `apiResponse(['assignment' => AssignmentResource::make($assignment->fresh())], 'Assignment created successfully', statusCode: 201)`.
- **Side effects (all inside one `DB::transaction()`, `AssignmentTrait::createAssignment()`):**
  - Creates a new `Topic` row from `assignment_topic` (module `Topic`), then sets `assignment_code = "AL-{course_id}"` immediately, then **re-saves** it as `"AL-{course_id}-{assignment.id}"` right after insert — two writes to `assignment_code` per creation, by design (the id isn't known until after insert).
  - If `topic_content` present, creates one `Modules\Topic\...\TopicDocDetail` row per entry (`title`/`link`/`note`) against the new topic.
  - Attaches `tags`: each `{key, value}` where `key == 0` **creates a brand-new `Tag`** (`type: Tag::ASSIGNMENT_TAG`) and attaches it; a nonzero `key` attaches the existing tag by id (no validation that the tag actually belongs to `Tag::ASSIGNMENT_TAG` — any existing tag id, of any type, can be attached here).
  - **`createAssignmentsForPackageStudents($courseId, $assignment)` — cross-module write into `StudentAssignment`:** loads every `Enrollment` for `$courseId` (via `EnrollmentRepositoryInterface::enrollmentsWithASpecificCourseId`) and creates one `Modules\StudentAssignment\Entities\StudentAssignment` row per enrollment, copying `number_of_exercises` and (only if `assignment->is_ai_enabled`) `ai_model_id`/`assignment_instruction_link`/`assignment_sample_feedback_link` — **every currently-enrolled student in the course is retroactively assigned this new template immediately on creation**, synchronously, in the same request/transaction. This is a materially different distribution mechanism from `StudentAssignment`'s own `assign-by-filters` bulk-assignment endpoint (see `StudentAssignment.md`) — the two paths can both create `StudentAssignment` rows for the same course from different triggers.
  - `handleAIFilesUpload()`: if `assignment_instruction_file`/`assignment_sample_feedback_file` was uploaded as an actual file, clears the model's existing Spatie MediaLibrary collection (`assignment_instruction`/`assignment_sample_feedback`) and re-adds it, then overwrites the `..._link` column with the new media URL — a string value for the same field instead sets the link column directly with no media library interaction.
- **Notes:** if `ai_model` (no `_id`) is present on the request but `ai_model_id` is not, it's merged in as `ai_model_id` before persistence — a body key naming inconsistency the client can exploit but that a parity test should also cover (only `ai_model` without `_id` and without `ai_model_id` set).

## `POST /v1/assignment-library/status/change` — `changeStatus()` (`AssignmentController`)
- **Request body:** validated inline via `Validator::make()` (no FormRequest class): `assignment_ids` required array, each `exists:assignments,id`; `comment` required string; `status` required, one of `activate`/`deactivate`.
- **Success response:** `apiResponse([], 'Assignments deactivated successfully')` or `apiResponse([], 'Assignments activated successfully')` (200 both branches).
- **Side effects:** bulk `Assignment::whereIn('id', ...)->update(['status' => ...])`; `App\Traits\ActivationAndDeactivationProcess::addActivityLogsAndComments()` bulk-inserts one `Spatie\Activitylog\Models\Activity` row **and** one `App\Models\DeactivatingComment` row per assignment id (log name `assignment_activation_and_deactivation`), both via raw `->insert()` (bypasses model events/observers).
- **Notes:** no dedupe on `assignment_ids` beyond `->unique()` inside the activity-log helper — the underlying `update()`/comment-insert still processes duplicates in the array as given.

## `GET /v1/assignment-library/{assignment}/logs` — `activityLogs()` (`AssignmentController`, route name `bootcamp-course.logs` — misleading name, this route is not bootcamp-specific)
- Query: `rows` (optional int, default 15).
- **Success response:** `ActivityLogResource::collection($paginator)->additional(['meta' => ['next_page_url', 'prev_page_url', 'range' => ['from','to','total']]])` — uses Laravel's own `cursor`-type paginator (`Activity::forSubject($assignment)->...->paginate($rows, $columns, 'cursor')`), **not** this module's custom base64-JSON cursor scheme used everywhere else in this file — `meta` here additionally carries real `next_page_url`/`prev_page_url` strings from Laravel's paginator, a shape unique to this one endpoint in the module.
- Route-model-binding miss on `{assignment}` → standard 404 `ModelNotFoundException` shape (see common conventions).

## `PUT /v1/assignment-library/{assignment}` — `update()` (`AssignmentController`)
- **Request body** (`UpdateAssignmentRequest`): same field set as `StoreAssignmentRequest` but every field `nullable` instead of `required` (no `course_id`/`package_id` field at all — cannot be changed via this endpoint).
- **Success response:** `apiResponse(['assignment' => AssignmentResource::make($assignment->fresh())], 'Assignment updated successfully')` (200).
- **Side effects (`AssignmentTrait::updateAssignment()`, one `DB::transaction()`):**
  - If `assignment_topic` sent, updates the linked `Topic.title` (not a new topic — same row).
  - `allowed_file_types` handled specially: if present, saved directly to the model **before** the main `$assignment->update($updateFields)` call (with the key `unset` from `$updateFields` first) — two separate `UPDATE` statements instead of one when this field changes.
  - `topic_content`: **absence of the key entirely** deletes all existing `TopicDocDetail` rows for the topic; **presence** (even `[]`?) also deletes-then-recreates them — either way the old doc-detail set is fully replaced, never merged.
  - `syncTags()`: unlike `store()`'s `attachTags()` (additive), this calls `Tag::sync()` — **omitting `tags` entirely clears all existing tags** (`$assignment->tags()->sync([])`), a destructive default a client must actively avoid by resending the current tag set on every update.
  - **Cross-module propagation to `StudentAssignment`:** if any of `ai_model_id`/`assignment_instruction_link`/`assignment_sample_feedback_link`/`is_ai_enabled` were sent, those exact values are pushed onto every `StudentAssignment` row for this `assignment_id` **except** ones already `STATUS_SUBMITTED` or `STATUS_EVALUATED` — an in-progress-but-not-yet-submitted student assignment can have its AI config silently rewritten by a later template edit.

## `DELETE /v1/assignment-library/delete-multiple` — `deactivateMultiple()` (trait method, bound via `AssignmentController`)
- **Request body** (`DeactivateMultipleRequest`): `ids` required array; `ids.*` `exists:assignments,id`.
- **Success response:** `apiResponse([], 'Assignments deleted successfully')` — message says "deleted" but the actual effect (`AssignmentRepository::deactivateMultiple()`) is `UPDATE assignments SET status = STATUS_DEACTIVE WHERE id IN (...)` — **a soft status flip, not a real delete**; no row is removed and there's no `deleted_at`/soft-delete trait on `Assignment` at all.

## `GET /v1/assignment-library/count` — route registered, **no controller method exists**
`getAssignmentCounts` is named in the route (`->name('assignment-library.count')`) but confirmed absent from both `AssignmentController` and `AssignmentTrait` (grepped the full module tree). Calling this route triggers a PHP fatal `Error: Call to undefined method` — an uncaught-exception **500**, not a clean 404 — identical failure mode to the broken-`apiResource`-action pattern documented in `NPS.md`.

## Bootcamp assignment routes (`BootcampAssignmentController`, same `assignments` table, same `AssignmentTrait`)

### `GET /v1/bootcamp-assignment-library` — `index()`
- Query: `rows` (optional int, default 15). **No `course_id` filter at all** in `BootcampAssignmentController::index()` — unlike the regular `index()` above, this calls the same `assignmentRepo->allWithSearch()`, which still internally applies `->where('course_id', request('course_id'))` — so this endpoint has the identical "silently empty if `course_id` omitted" behavior, just reached through a different controller.
- **Success response:** `AssignmentResource::collection(...)->additional(['meta' => ['total' => $this->assignmentRepo->allWithSearchTotal(), 'range' => ...]])` — uses `AssignmentResource`, **not** `BootcampAssignmentResource` (see note below) — `meta.total` key name differs from the regular `index()`'s `total_assignment`.

### `POST /v1/bootcamp-assignment-library` — `store()`
- **Request body** (`StoreBootcampAssignmentRequest`): same core fields as `StoreAssignmentRequest` (`course_id`, `assignment_topic`, `number_of_exercises`, `assignment_type`, `plagiarism`, `word_count`, `status`, `topic_content`, `tags`) but **omits** `allowed_file_types`, `ai_model_id`, `is_ai_enabled`, `assignment_instruction_link`/`_file`, `assignment_sample_feedback_link`/`_file`, `package_id`, `assignment_download_file`, `ref_assignment_no` entirely from its rule set — none of those fields are validated on this path (though `createAssignment()` will still read/persist whichever of them happen to be present in the raw request, since the trait method doesn't distinguish which FormRequest called it).
- **Success response:** `apiResponse(['assignment' => AssignmentResource::make(...)], 'Bootcamp Assignment created successfully', statusCode: 201)` — same `AssignmentResource` shape as the regular endpoint (again, not `BootcampAssignmentResource`).
- **Side effects:** identical to the regular `store()` — same `createAssignment()` trait method, same retroactive `createAssignmentsForPackageStudents()` fan-out to every enrollment on `course_id`.

### `PUT /v1/bootcamp-assignment-library/{assignment}` — `update()`
- **Request body** (`UpdateBootcampAssignmentRequest`): nullable mirror of the Store variant, same omitted-field set.
- **Success response:** `apiResponse(['assignment' => AssignmentResource::make(...)], 'Bootcamp Assignment updated successfully')` — identical trait call (`updateAssignment()`) and side effects (including the `StudentAssignment` AI-field propagation and destructive tag-sync) as the regular `update()` above.

### ⚠️ `BootcampAssignmentResource` (`Modules/Assignment/Http/Resources/BootcampAssignmentResource.php`) is dead code
Grepped the entire `Modules/` tree: this class is defined but **never referenced by any controller** — both `BootcampAssignmentController::index()` and `::store()`/`::update()` use `AssignmentResource`, not this class. Its distinct shape (`course`, `package`, `creator`, `updater` nested objects, no `topic`/`allowed_file_types` exclusions matching the regular resource) is never actually returned by any live endpoint — do not build parity coverage assuming this shape appears anywhere.

### `GET /v1/assignment-library/{course_id}/export` — `export()` (trait method, bound via `BootcampAssignmentController` — route name is `assignment-library.export`, path segment says `assignment-library` despite being wired only under `BootcampAssignmentController`)
- Path param `course_id` — plain int, no `exists:courses,id` check anywhere in this action.
- **Request body:** inline `Validator::make($request->all(), ['data' => ['nullable','array']])` — `data` is an optional array of search/filter criteria consumed later by the job.
- **Success response:** `apiResponse('', 'Assignment Csv file exporting started')` — `data` is an empty **string**, matching the `NPS`-style export-ack pattern (see `NPS.md`).
- **Side effects:** dispatches `AssignmentCSVDownloadStart::dispatch($request->user(), $request->all(), $data['data'] ?? [], $course_id)` onto queue `default_medium`. The job builds a CSV (`Topic`,`Code`,`Type`,`Word Count`,`Status`,`Number of exercises`,`Added Date`) from `Assignment::where('course_id', $course_id)->groupBy('topic_id')->withSearchAndFilters(...)->latest('id')->lazy()`, uploads to S3 (`exports/tmp/assignments/{filename}`), then **both** `$user->notifyNow(new AssignmentCSVCompleteNotification(...))` (in-app `database`-channel notification only, delivered synchronously despite `notifyNow`'s name suggesting otherwise being unusual for a queued job) **and** `Mail::to($user->email)->send(new AssignmentCSVCompleteMail(...))` (a real queued-mailer send) fire — two separate completion signals, not a duplicate of the same channel.
  - ⚠️ **Copy-paste artifact in the notification payload:** `AssignmentCSVCompleteNotification::toArray()` hardcodes `'title' => 'User CSV exporting completed'` and `'description' => 'User csv export completed, Find the link below.'` — both say **"User"**, not "Assignment"; this class was evidently cloned from `Modules\User\Notifications\UserCSVCompleteNotification` and the copy was never updated. The in-app notification a staff user sees after an *assignment* CSV export will read "User CSV exporting completed." Preserve this text verbatim in parity assertions — it is a real, currently-shipping string, not a hypothetical bug.
  - No "export started" email is queued for this module (contrast with `NPS`'s export, which sends both a started and a completed mail) — only the one completion mail/notification pair above.

## Summary of endpoints documented

**9 live, working endpoints** across `Modules/Assignment/Routes/api.php`: `index`/`store`/`changeStatus`/`activityLogs`/`update`/`deactivateMultiple` (regular), `index`/`store`/`update` (bootcamp), plus `export` (bound to the bootcamp controller but path-named for the regular listing) — 10 total routes registered, 1 of which (`GET /v1/assignment-library/count`) is confirmed **broken** (fatal 500, no method exists).

**Notable findings for parity testing:**
- `GET /v1/assignment-library/count` — dead route, undefined method, fatal 500.
- Both `index()` variants silently return an empty page (not an error) if `course_id` is omitted, because the repository's `WHERE course_id = ?` is unconditional rather than `when()`-guarded.
- `BootcampAssignmentResource` is fully dead code — never invoked by any route.
- `AssignmentCSVCompleteNotification`'s in-app payload text says "User" instead of "Assignment" — a real, shipping copy-paste bug, not a typo to "fix" when asserting.
- Creating **or updating** a template via either flow fans out writes into the `StudentAssignment` module's table (retroactive assignment to every current enrollee on create; AI-field propagation to not-yet-submitted student assignments on update) — a parity test for this module's `store`/`update` must also assert on `student_assignments` rows, not just the `AssignmentResource` response body.
- `deactivateMultiple`'s response message says "deleted" but the effect is a status flip (`STATUS_DEACTIVE`) — no row is ever removed, no soft-delete column exists on `Assignment`.
- `update()`'s `tags` handling is destructive-by-omission (`sync([])` if the key is absent) while `store()`'s is purely additive (`attach()`) — asymmetric semantics between create and update for the same relation.

**Confidence:** High — every endpoint traced to its controller/trait method and the actually-invoked FormRequest/Resource classes; the dead-route, dead-resource, and copy-paste-notification findings were independently confirmed via full-tree grep, not inferred from naming.
